React Native — это фреймворк от Facebook (Meta) для создания **мобильных приложений** под **iOS и Android** на **JavaScript и React**.

### То есть:

Если ты уже знаешь **React** для веба, то в React Native ты пишешь похожим образом — компоненты, пропсы, стейт — но вместо HTML-тегов (`div`, `span`) используешь **нативные компоненты** (`View`, `Text`, `Image`), которые отображаются как **реальные элементы интерфейса на телефоне**.

### Главная идея

Ты **пишешь код один раз**, и он работает на **двух платформах**:

- Android
    
- iOS
    

### Как это работает

React Native использует **JavaScript** для логики и **нативные компоненты** для отображения.  
То есть приложение выглядит **как настоящее нативное**, а не веб-страница внутри приложения.

### Пример компонента в React Native:

```js
import { View, Text } from "react-native";

export default function App() {
  return (
    <View style={{ padding: 20 }}>
      <Text>Hello from React Native!</Text>
    </View>
  );
}
```

### Где используется

React Native используется крупными компаниями:

- Instagram
    
- Facebook
    
- Discord
    
- Tesla
    
- Shopify
    

### Плюсы

✅ Один код → две платформы  
✅ Быстрая разработка  
✅ Реальные нативные компоненты (приложения не тормозят как WebView)

### Минусы

⚠ Иногда нужно писать **нативный код (Java/Kotlin, Swift)**, если нужно что-то очень специфическое.

---

История появления **React Native** связана с тем, как Facebook решал проблему разработки мобильных приложений **быстро** и **одновременно для iOS и Android**.

---

## 🔹 Предыстория

В 2013 году Facebook активно развивал React для веба.  
React оказалась **очень удобной**: компоненты, быстрый интерфейс через Virtual DOM и повторное использование кода.

Но у Facebook была проблема:

- Нужно поддерживать **два мобильных приложения** (iOS и Android).
    
- Каждую фичу приходилось **писать два раза**:
    
    - На **Objective-C/Swift** для iOS
        
    - На **Java/Kotlin** для Android
        

Это занимало много времени и усложняло синхронизацию изменений.

---

## 💡 Идея, которая всё изменила

Инженер Facebook **Джордан Уолке** (создатель React) в 2013 году сделал эксперимент:

> Он заставил **JavaScript код управлять нативными UI-компонентами iOS**.

То есть:  
JS → нативные кнопки, поля, списки → результат не выглядит как веб, а **как настоящее нативное приложение**.

Это было революционно.  
Так родилась идея:  
**“Если можно управлять нативным интерфейсом через JavaScript, значит можно писать одно приложение для всех платформ!”**

---

## 🚀 Хакатон внутри Facebook (2013)

На внутреннем хакатоне разработчики собрали прототип будущего React Native.

Этот прототип:

- запускал React-компоненты на телефоне
    
- заменял HTML-теги на нативные элементы
    

Команде понравилось — проект начали развивать.

---

## 🧱 Главное отличие подхода

React Native **не использует WebView** (как многие кросс-платформенные решения раньше).

❌ Не превращает приложение в «веб внутри телефона».  
✅ Он **отрисовывает реальные нативные компоненты**.

JS → специальный “мост” → Нативные элементы платформы.

---

## 🌍 Официальный релиз

React Native впервые показали на **React Conf 2015**, а позже сделали **open-source**.

Сначала была поддержка **iOS**, через несколько месяцев — **Android**.

---

## 💼 Почему Facebook сделал React Native

|Проблема|Решение|
|---|---|
|Две команды для двух платформ|Один код → два приложения|
|Долгий development cycle|Быстрая разработка + Hot Reload|
|Разные UX и логику сложно синхронизировать|Компонентный подход React|

React Native появился не просто как «новый фреймворк», а как **решение конкретных серьёзных проблем**, которые существовали в мобильной разработке до него.  
Главная цель — **разрабатывать мобильные приложения быстрее, дешевле и проще**, не жертвуя качеством.

---

## ✅ **1. Проблема: Две разные команды для iOS и Android**

До React Native:

|Платформа|Язык|Команда|
|---|---|---|
|iOS|Objective-C / Swift|iOS-разработчики|
|Android|Java / Kotlin|Android-разработчики|

Нужно было **дублировать всю работу**: интерфейсы, логику, API, стили.

### Как решает React Native:

- Один код на **JavaScript + React**
    
- Один компонентный подход
    
- Приложение работает на **обеих платформах**
    

👉 **Одна команда → два приложения.**

---

## ✅ **2. Проблема: Долгий цикл разработки**

Раньше, чтобы увидеть изменения, нужно было:

1. перекомпилировать проект
    
2. заново установить на устройство
    

Это занимало **минуты**.

### Что сделал React Native:

- **Hot Reload / Fast Refresh**
    
- Изменения в коде видны **сразу**, без перезапуска приложения.
    

👉 Разработка стала намного быстрее.

---

## ✅ **3. Проблема: Кроссплатформенные приложения были _тормозными_**

До React Native использовали:

- Cordova
    
- Ionic
    
- PhoneGap
    

Они показывали интерфейс **через WebView**, т.е. это был браузер в приложении → результат **медленный и ненативный**.

### Как решает React Native:

React Native **использует нативные UI-компоненты** платформы.

JS → “мост” → **реальные нативные кнопки, списки и навигация**.

👉 Приложения выглядят **как настоящие нативные**, а не как сайт в телефоне.

---

## ✅ **4. Проблема: Сложно переиспользовать код с веба**

React принёс **компонентное мышление**.  
Но на мобильных раньше всё писалось «вручную» под платформу.

### React Native:

- повторяет **структуру и концепции React**
    
- позволяет **переиспользовать бизнес-логику** между вебом и мобильными приложениями
    

👉 Разработчикам с web-опытом стало **легко перейти в мобильную разработку**.

---

## ✅ **5. Проблема: Сложно быстро выпускать обновления**

App Store и Google Play заставляли **каждый раз** ждать публикации.

### React Native + CodePush:

Позволяет **обновлять код приложения “по воздуху”** (без публикации новой версии в магазинах).

👉 Быстрые фиксы, UI-апдейты и тестирование.

---

## ✅ **6. Проблема: Затраты на разработку и поддержку высокие**

- 2 команды
    
- 2 кода
    
- 2 набора багов  
    → Всё стоит дорого.
    

### React Native:

- сокращает количество разработчиков
    
- уменьшает стоимость поддержки
    
- ускоряет релизы
    

👉 Идеален для стартапов и крупных компаний.

---

## 🏁 Итог

React Native решил **ключевые боли мобильной разработки**:

| Проблема                           | Решение React Native                                 |
| ---------------------------------- | ---------------------------------------------------- |
| Нужно писать код два раза          | ✅ Общий код для iOS и Android                        |
| Медленный цикл разработки          | ✅ Fast Refresh (почти мгновенный просмотр изменений) |
| WebView-приложения были тормозными | ✅ Реальные нативные UI-компоненты                    |
| Сложно привлекать разработчиков    | ✅ Можно использовать JS-разработчиков                |
| Дорого поддерживать два приложения | ✅ Снижение затрат на разработку и поддержку          |

Hа Windows невозможно запустить iOS эмулятор**, потому что:

- **iOS Simulator — часть Xcode**
    
- **Xcode работает только на macOS**
    
- **Apple не разрешает запускать iOS эмуляторы вне macOS**
    

Это **не ограничение React Native**, это **ограничение Apple**.

---

## 🔥 Почему так?

Apple использует **закрытую экосистему**:

|Что|Где работает|
|---|---|
|Xcode|только macOS|
|iOS Simulator|только macOS|
|Инструменты сборки для iOS|только macOS|

То есть чтобы **собирать** и **запускать** приложение на iPhone или симуляторе, ты **обязан** иметь macOS.

И он может просто стоять в углу, никто не обязан на нём работать.

# React Native CLI

**React Navigation** — это самая популярная библиотека для **навигации в React Native**.  
Она позволяет создавать **экраны** и **переходы между ними**, например:

- переходы по кнопкам
    
- вкладки (Tab)
    
- боковое меню (Drawer)
    
- стек экранов (Stack Navigation)
    

---

## 🔧 Зачем нужна React Navigation?

В вебе мы можем переходить между страницами через URL.  
В мобильных приложениях у нас **экраны**, и надо управлять тем, какой экран сейчас активен.

React Native сам навигацию не предоставляет → поэтому появилась **React Navigation**.

---

## 🚀 Установка (React Native CLI)

```bash
npm install @react-navigation/native
```

Дополнительные зависимости:

```bash
npm install react-native-screens react-native-safe-area-context
```

Для Stack Navigator:

```bash
npm install @react-navigation/native-stack
```

---

## 📱 Простейший пример навигации (Stack Navigation)

### `App.js`

```js
import * as React from 'react';
import { NavigationContainer } from '@react-navigation/native';
import { createNativeStackNavigator } from '@react-navigation/native-stack';
import HomeScreen from './HomeScreen';
import DetailsScreen from './DetailsScreen';

const Stack = createNativeStackNavigator();

export default function App() {
  return (
    <NavigationContainer>
      <Stack.Navigator>
        <Stack.Screen name="Home" component={HomeScreen} />
        <Stack.Screen name="Details" component={DetailsScreen} />
      </Stack.Navigator>
    </NavigationContainer>
  );
}
```

### `HomeScreen.js`

```js
import { View, Text, Button } from 'react-native';

export default function HomeScreen({ navigation }) {
  return (
    <View>
      <Text>Home Screen</Text>
      <Button title="Go to Details"
        onPress={() => navigation.navigate('Details')}
      />
    </View>
  );
}
```

### `DetailsScreen.js`

```js
import { View, Text } from 'react-native';

export default function DetailsScreen() {
  return (
    <View>
      <Text>Details Screen</Text>
    </View>
  );
}
```

# Expo


**Expo** — это инструмент и экосистема, которая упрощает разработку React Native приложений.  
Если React Native — это «двигатель», то **Expo — это удобная обёртка вокруг него**.

---

## 🔥 Что делает Expo проще?

Без Expo:

- Нужно настраивать Android Studio
    
- Нужно настраивать Xcode (а он только на Mac)
    
- Нужно вручную ставить нативные библиотеки
    
- Сборка может быть сложной
    

С Expo:

- Можно начать **без Android Studio и без Mac**
    
- Можно смотреть приложение **прямо на телефоне** с помощью **Expo Go**
    
- Всё запускается буквально за пару минут
    

---

## 🚀 Установка и запуск

```bash
npm install --global expo-cli
```

Создать проект:

```bash
npx create-expo-app myApp
```

Запуск:

```bash
cd myApp
npm start
```

Дальше ты увидишь QR-код → просто сканируешь через приложение **Expo Go** на телефоне → приложение запускается **сразу**.

---

## 📱 Главные преимущества Expo

|Возможность|Expo|React Native CLI|
|---|---|---|
|Запуск без Android Studio|✅ Да|❌ Нет|
|Запуск на iPhone без Mac|✅ Да|❌ Нет|
|Быстрая разработка|✅ Да|✅ Да|
|Доступ к нативным API (камера, GPS, Bluetooth и т.д.)|✅ Через Expo SDK|✅ Через отдельные пакеты|
|Сборка приложений для App Store / Play Store без Mac|✅ Через Expo EAS Build|❌ Нужен Mac для iOS|

---

## 🧱 Что входит в Expo?

Expo предоставляет огромный набор готовых функций, например:

```js
import * as Camera from 'expo-camera'
import * as Location from 'expo-location'
import * as Notifications from 'expo-notifications'
```

То есть можно легко использовать:

- Камеру
    
- Микрофон
    
- Уведомления
    
- Геолокацию
    
- Сканеры QR-кодов
    
- Хранилище
    
- Bluetooth и т.д.
    

---

## ⚠️ Важный момент: Managed vs Bare Workflow

|Тип|Для кого|Суть|
|---|---|---|
|**Managed Workflow**|Начинающие и средние|Всё работает «из коробки», нативный код трогать не нужно|
|**Bare Workflow**|Продвинутые|Можно писать нативный код на Swift/Java|

Ты начинаешь в **Managed**, если нужно — можно «выйти» в Bare.

---

## 🎯 Когда Expo идеален?

- Стартапы
    
- Учебные проекты
    
- MVP / прототипы
    
- Когда нужно быстро показать приложение клиенту
    
- Когда нет Mac ☺️
    

---

## ☝️ Когда лучше без Expo?

- Когда нужно писать **нативные модули**
    
- Когда нужен **очень специфический доступ к железу**
    

Но даже в этих случаях Expo теперь поддерживает **config plugins**, так что ограничений стало меньше.
